# 第 1 步验收：业务流程与角色权限

本文档是 V2 的流程基准。页面、接口和数据库必须遵守这里的状态与权限，不允许在组件中另写一套判断。

## 一、策略确认

策略包含两类：

1. 官网内容策略。
2. Gap 内容策略。

### 代运营模式

运营确认策略 → 客户确认策略 → 策略确认完成 → 创建对应任务并进入优化中心。

运营未确认时，客户只能查看“待运营确认”，不能提前确认。运营或客户在各自确认阶段可以忽略；忽略后终止，不创建任务。

### Agent 自主模式

客户确认策略 → 策略确认完成 → 创建对应任务并进入优化中心。

客户在确认阶段可以忽略；忽略后终止，不创建任务。

## 二、官网内容任务

### 代运营模式

待运营审核 Brief → 运营配置知识、保存并确认 → 内容生成与质检 → 运营修改、保存并审核 → 客户查看最新版本，也可修改和保存 → 客户确认最终稿 → 官网审核。

官网通过后完成。

官网拒绝后，必须携带拒绝原因进入“官网退回 · 待运营修改”：

运营修改并保存 → 运营重新审核 → 客户再次确认 → 重新提交官网审核。

退回后的流程不能忽略，循环直至官网通过。

### Agent 自主模式

待客户审核 Brief → 客户配置知识、保存并确认 → 内容生成与质检 → 客户修改、保存并确认最终稿 → 官网审核。

官网拒绝后，必须携带拒绝原因进入“官网退回 · 待客户修改”：

客户修改并保存 → 客户重新确认 → 重新提交官网审核。

退回后的流程不能忽略，循环直至官网通过。

## 三、外部内容任务

代运营模式沿用“运营审核 Brief → 生成与质检 → 运营审核 → 客户最终确认”的角色交接。

Agent 自主模式由客户完成 Brief 审核、正文修改和最终确认。

客户确认最终稿后任务直接完成，提供复制内容，不进入官网审核。

## 四、技术修复任务

技术修复直接提交官网处理，不进入策略审核后的内容生产流程，不生成 Brief，也不进行运营或客户内容审核。

页面只展示官网处理进度、处理结果和处理说明，操作统一为“查看详情”。

## 五、修改、保存与版本

1. 运营和客户都可以在自己负责的正文阶段直接修改并保存。
2. 每次保存都产生新版本，记录保存人、保存时间和版本号。
3. 角色交接后，下一位处理人默认看到上一位保存的最新版本。
4. 质检结果必须关联具体正文版本；正文更新后重新计算质检。
5. 审核记录必须保存操作人、原状态、新状态、意见和时间。

## 六、禁止的流转

- 官网拒绝后不能忽略或直接完成。
- 代运营模式下客户不能越过运营提前处理。
- Agent 自主模式不插入运营审核节点。
- 外部内容不能进入官网审核。
- 技术修复不能进入 Brief、生成内容或内容审核。
- 不存在 Re-check、已恢复、仍存在。
- 一个问题只生成一个 Brief，不自动合并问题。
