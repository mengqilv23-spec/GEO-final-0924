# V2 架构约束

## 单一事实来源

业务状态只保存于后端数据库。前端只根据 API 返回值渲染，不再使用散落的全局变量、DOM 文本或 localStorage 作为业务真相。

## 分层

1. `packages/domain`：任务类型、状态、角色权限、流转规则。
2. `apps/api`：鉴权、业务用例、数据持久化、外部系统回调。
3. `apps/web`：页面与交互，不自行推断状态。
4. PostgreSQL：问题、Brief、正文、质检、审核记录、官网回执的真实数据。

## 核心边界

- 诊断问题与执行任务是两个实体。
- 每个问题只能创建一个 Brief；不自动合并问题。
- 技术修复由官网回传处理状态和处理说明。
- 内容正文可直接编辑并保存；质检结果由正文版本计算。
- 官网内容与外部内容共用生成和审核能力，但结束路径不同。
- 候选策略统一更名为“认知缺口策略”，与官网 GEO 体检的问题序号独立。

## 禁止项

- 不使用 MutationObserver 修补业务逻辑。
- 不通过替换标签伪造新数据。
- 不在组件内复制状态机。
- 不引入 Re-check、已恢复、仍存在等未确认流程。
