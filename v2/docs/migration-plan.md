# 旧版到 V2 的迁移顺序

## 第一阶段：骨架与规则（当前）

- 建立 Web、API、Domain 三层。
- 固化三类任务与两种服务模式。
- 建立状态机，确保操作与状态由同一规则计算。

## 第二阶段：真实数据

- 接入 PostgreSQL。
- 建立 Finding、Task、Brief、ContentDocument、QualityResult、AuditRecord、WebsiteReturn 表。
- 增加登录、角色和项目数据隔离。
- API 写操作使用幂等键与审计日志。

## 第三阶段：逐页迁移

1. 官网 GEO 体检。
2. 买家人设、决策因子与认知缺口。
3. 认知缺口策略。
4. 优化中心与 Brief。
5. 内容编辑、质检与审核。
6. 知识库选择、上传与联网辅助。

## 第四阶段：外部协同

- AI 建站接收任务与回传官网处理结果。
- 知识库每次打开主动刷新已解析内容。
- 联网来源标记、事实确认和审核提示。

## 第五阶段：切换

- 以真实数据回放完整流程。
- 覆盖 Agent 自主与代运营的角色测试。
- 新版本部署到固定链接。
- 验收后再决定是否替换旧版；旧版在此之前保持不动。
