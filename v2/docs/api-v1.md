# 第 3 步验收：后端流转接口

本步骤把第 1 步的业务状态机和第 2 步的数据库连接起来。页面以后只能调用接口改变状态，不能自行修改显示结果。

## 已实现的操作

### 策略

- 运营确认或忽略官网内容策略、Gap 内容策略。
- 运营确认后，客户才能确认或忽略。
- Agent 自主模式由客户直接确认或忽略。
- 每次操作写入策略日志。

### Brief

- 当前处理人可以保存一句话要求、联网搜索开关和知识选择。
- Brief 每次保存都会递增版本号。
- 只能选择状态为“已可用”的知识。
- 上传后等待 AI 建站解析的资料不能被选择。
- 非当前处理人和错误状态不能修改 Brief。

### 正文

- 当前处理人可以直接修改和保存正文。
- 每次保存自动创建新版本，不覆盖旧版本。
- 保存记录包含保存人、角色、修改说明和操作时间。
- 重复提交同一个请求不会产生重复版本。

### 审核与状态流转

- Brief 确认、内容生成、运营审核、客户确认和官网审核均通过统一接口执行。
- 接口使用状态机检查角色权限和当前状态。
- 状态已被其他人修改时，旧请求会失败并要求刷新。
- 每次动作同时写入任务事件与审核记录。

### 官网回执

- 官网拒绝必须附带修改意见。
- 官网回执保存处理结果、处理人或处理系统、提交次数和原始返回内容。
- 同一次提交的处理中、通过或拒绝使用同一个提交次数，更新同一条回执，不会误算成多次提交。
- 官网拒绝后自动退回运营或客户，不能忽略。
- 修改和确认后可以再次提交官网。

### 双方日志

客户与运营均可读取任务的：

- 完整状态事件。
- 审核和确认记录。
- 正文全部历史版本。
- 官网每次处理回执。

## 防错机制

1. 每个写操作携带唯一请求编号，防止重复点击。
2. 更新时校验数据库中的当前状态，防止多人同时覆盖。
3. 校验当前处理角色，防止客户越过运营。
4. 所有状态变化和保存操作都有审计记录。
5. 官网拒绝没有修改意见时拒绝受理。

## 当前接口入口

- `POST /api/v2/strategies/:strategyId/actions`
- `PUT /api/v2/tasks/:taskId/brief`
- `PUT /api/v2/tasks/:taskId/content`
- `POST /api/v2/tasks/:taskId/actions`
- `GET /api/v2/tasks/:taskId/history`

## 已确认的接口规则

1. 忽略必须填写原因；没有原因时接口拒绝操作。
2. 运营和客户都可以在自己负责的阶段修改并保存正文，非当前处理人只能查看。
3. 提交官网后不允许撤回，只能等待官网通过或拒绝。
4. 日志只支持双方查看，不提供导出功能。
