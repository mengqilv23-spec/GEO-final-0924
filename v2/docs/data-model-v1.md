# 第 2 步验收：真实数据模型

V2 不再把页面文案、按钮状态或 localStorage 当作业务数据。所有状态和修改记录都由数据库保存。

## 1. 项目与角色

每个项目保存服务模式：Agent 自主或代运营。

项目成员保存真实角色：客户、运营、Agent、官网。接口会根据项目模式、当前角色和任务状态决定是否允许操作。

## 2. 策略

官网内容策略和 Gap 内容策略分别保存：

- 所属项目和序号。
- 标题与策略内容。
- 当前状态和当前处理角色。
- 确认人、确认时间。
- 忽略人、忽略原因和忽略时间。

代运营模式中，运营未确认前不会给客户开放确认或忽略操作。

## 3. 诊断问题

每个问题保存：

- 独立序号。
- 来源模块。
- 任务类型：技术修复、官网内容或外部内容。
- 异常标题、所属检查项、说明和优先级。
- 原始检测证据。

问题序号和认知缺口策略序号分别管理，二者不混用。

## 4. 任务

任务保存来源、任务类型、当前状态、当前处理角色和官网最新反馈。

系统对来源建立唯一约束：

- 一个诊断问题最多生成一个任务。
- 一条策略最多生成一个任务。
- 不会把多个问题自动合并成一个任务。

## 5. Brief 与知识

每个任务最多有一个 Brief，保存：

- 用户输入的一句话要求。
- 是否使用联网搜索。
- 当前版本、保存人和确认人。
- 已选择的知识条目。

知识条目区分知识库资料、上传文件、人工说明和联网资料。上传文件在 AI 建站解析完成前为“等待解析”，不能作为已可用知识选择。

## 6. 正文与版本

正文不覆盖旧内容，每次保存都生成新的版本，记录：

- 完整正文。
- 版本号。
- 内容来源。
- 保存人和保存角色。
- 修改说明和保存时间。

角色交接后读取最新版本，同时仍能查看历史版本。

## 7. 内容质检

每次质检必须关联具体正文版本，保存通过数量、总项目数和每条问题的位置、严重程度与说明。

正文改变后不会沿用旧版本的质检结果。

## 8. 审核与流转记录

运营审核、客户确认、忽略、提交官网和官网退回都会写入审核记录和任务事件，包含：

- 操作人和角色。
- 操作前状态与操作后状态。
- 审核意见。
- 操作时间。
- 防止重复提交的唯一标识。

## 9. 官网回执

每次提交官网都按次数保存独立回执，包括处理中、通过、拒绝或失败，以及官网返回的说明。

官网拒绝不会覆盖之前的记录；修改后重新提交会产生下一次回执。

## 本步骤需要确认

1. 上述信息是否足够支撑实际业务。
2. 哪些字段属于客户敏感信息，需要限制运营或 Agent 查看。
3. 官网回执还需要保存哪些具体信息。
4. 正文历史版本需要永久保留，还是允许按期限归档。
