# 第 4 步：策略确认页面

本页用于验收官网内容策略和 Gap 内容策略的确认流程。

## 需要检查

1. 代运营模式默认进入运营视角。运营可以确认或忽略，忽略必须填写原因。
2. 切换到客户视角时，如果运营尚未确认，客户只能查看详情，不能确认或忽略。
3. 运营确认后，状态立即变为“待客户确认策略”，当前处理人变为客户。
4. 客户确认后，状态立即变为“策略已确认”，操作变为“去优化中心”。
5. 客户在自己负责的确认阶段也可以忽略；忽略后终止，不生成任务。
6. Agent 自主模式没有运营节点，客户可直接确认或忽略。
7. 页面可按“全部 / 官网内容策略 / Gap 内容策略”筛选。
8. 一条策略确认完成后只生成一个优化任务。

## 实现说明

- 页面调用 `@geo/domain` 中的统一策略状态机判断权限和状态变化。
- 页面演示数据集中在 `src/demo/strategies.ts`，不包含散落在组件里的业务判断。
- 后端新增项目策略列表接口：`GET /api/v2/projects/:projectId/strategies`。
- 正式接入数据库后，用接口返回数据替换演示数据，交互和权限规则保持不变。

## 确认结果

状态：**已确认**

确认规则：

1. 代运营模式下，运营可以“确认策略”或“忽略”。
2. 运营确认前，客户只能“查看详情”。
3. 运营确认后，客户才能确认或忽略。
4. 客户确认后，状态变为“策略已确认”，按钮变为“去优化中心”。
5. Agent 自主模式下，客户可以直接确认或忽略。
6. 忽略必须填写原因。

后续实现必须复用统一状态机，不得在页面中另写一套角色权限。
