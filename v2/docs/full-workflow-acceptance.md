# V2 完整执行闭环

## 代运营模式

运营确认官网内容策略和 Gap 内容策略 → 客户确认策略 → 进入优化中心 → 运营审核 Brief、配置知识并保存 → Agent 生成内容和质检 → 运营修改、保存并审核 → 客户查看最新版本，可修改和保存 → 客户确认最终稿 → 官网审核。

官网通过后完成。官网拒绝时，修改意见退回运营 → 运营修改、保存并重新审核 → 客户再次确认 → 重新提交官网，循环至通过。官网退回后不能忽略。

## Agent 自主模式

客户确认官网内容策略和 Gap 内容策略 → 进入优化中心 → 客户审核 Brief、配置知识并保存 → Agent 生成内容和质检 → 客户修改、保存并确认最终稿 → 官网审核。

官网拒绝时，意见直接退回客户 → 客户修改并保存 → 重新确认 → 再次提交官网，循环至通过。

## 特殊任务

- 技术修复由官网直接处理并返回状态和处理说明，不进入 Brief 和内容审核流程。
- 外部内容在客户确认最终稿后完成，不提交官网审核，并提供复制内容按钮。
- 官网提交后不允许撤回。
- 忽略必须填写原因；只有当前负责的确认或审核角色可以忽略。
- 代运营模式中，客户不能在运营完成前置确认前操作。

## 数据与日志

- 策略、诊断问题、任务、Brief、知识选择、正文版本、质检结果、审核记录和官网审核结果全部保存。
- 运营和客户看到同一份最新保存版本。
- 日志双方可见且只读。
- 官网结果保存通过、拒绝或失败、修改意见、返回时间、提交次数、原始结果以及官网处理人或处理系统。
- 项目进行期间永久保留；项目结束两年后归档，不直接删除。
- 流程中不存在 Re-check 节点。
